🧩 Comment le site est construit

Le site tient en trois éléments, tous placés dans le même dossier sur l'hébergement OVH :

  • index.html — le site lui-même. On n'y touche jamais directement.
  • content.json — tous les textes, prix, cours et coordonnées du site. C'est ce fichier que cette page (admin.html) permet de modifier facilement, sans écrire une ligne de code.
  • le dossier images/ — toutes les photos du site (et images/galerie/ pour les photos des chiens accompagnés).

Le principe est donc toujours le même en trois temps : 1) je modifie dans cette page admin, 2) je télécharge le fichier content.json mis à jour, 3) je le dépose sur l'hébergement OVH à la place de l'ancien. Le site est alors à jour pour tout le monde.

💡
Rien n'est jamais perduCette page garde automatiquement un brouillon de tes modifications dans le navigateur, même si tu fermes l'onglet par accident. Le bouton ↶ (annuler) en bas permet aussi de revenir en arrière à tout moment.

🗂️ L'admin en détail : les panneaux

La page admin.html est composée de 13 panneaux (les blocs qu'on ouvre/ferme en cliquant sur leur titre), plus trois outils globaux en haut et en bas de page. Chaque panneau modifie une partie précise du fichier content.json — jamais index.html directement. Voici, panneau par panneau, ce qu'il contrôle et à quoi ça correspond dans le fichier.

🔤
Pour lire les extraits ci-dessousCertains encadrés grisés montrent à quoi ressemble le fichier content.json « vu de l'intérieur » — c'est juste à titre d'exemple, il n'y a jamais besoin d'y toucher soi-même. Deux mots reviennent souvent : true veut dire « activé / affiché sur le site », et false veut dire « désactivé / caché ». Un clic sur un interrupteur dans l'admin bascule automatiquement entre les deux — pas besoin de taper ces mots.

👁 Visibilité du site

visibility.*

7 interrupteurs qui cachent ou montrent des blocs entiers du site (Présentation, Pourquoi, Étiquettes, Galerie, Carte, Facebook, Instagram) sans jamais supprimer leur contenu.

"visibility": { "pourquoi": true, ← affichée sur le site "galerie": false ← cachée du site }

Exemple : éteindre l'interrupteur « Pourquoi » fait passer sa valeur à false et la section disparaît du site. La rallumer repasse la valeur à true et la section réapparaît, exactement comme avant — son texte n'a jamais bougé du panneau « Pourquoi » entre-temps.

Coordonnées de contact

contact.*

Email, téléphone, ville, zone d'intervention, liens Facebook et Instagram.

"contact": { "email": "Morgane@momoxdogs.fr", "telephone": "07 82 25 26 88", "ville": "Taverny, France" }

Ce sont ces champs qui alimentent les boutons « Appeler » / « Écrire » et la zone de texte affichés dans la section Contact du site.

Page d'accueil

hero.*

Le badge, le grand titre et le texte d'introduction tout en haut du site (première chose vue par un visiteur).

"hero": { "titre": "Une éducation canine <em>sur-mesure</em>, pas à pas." }

La balise <em>...</em> autour d'un mot l'affiche en italique doré sur le site — c'est la seule mise en forme HTML autorisée dans ce champ.

Présentation

presentation.*

Le titre et les deux paragraphes de la section « Bonjour, je suis Morgane ».

"presentation": { "titre": "Bonjour, je suis Morgane." }

Section « Pourquoi »

pourquoi.*

Eyebrow, titre, deux paragraphes et la citation mise en avant de la section « Pourquoi suivre des cours ? ».

"pourquoi": { "citation": "Il n'existe pas une méthode unique…" }

Ce panneau reste rempli même si la section est masquée depuis « 👁 Visibilité du site » — pratique pour préparer un texte avant de le publier.

Étiquettes

tags (liste)

Les petits mots-clés affichés sous la présentation (ex. « Éducation canine »). On en ajoute ou on en retire un par un.

"tags": [ "Éducation canine", "Balades canines" ]

Cliquer sur « Ajouter » insère une nouvelle entrée à la fin de cette liste ; la croix sur une étiquette la retire.

Cours & tarifs

services (liste d'objets)

Le panneau le plus riche : chaque carte est une prestation, avec sa catégorie, son titre, son image, sa description, son prix et sa visibilité propre.

{ "categorie": "Éducation", "titre": "Cours individuel", "image": "images/service-individuel.jpg", "description": "…", "prix": "50 €", "unite": "/ heure", "visible": true }

Les flèches ↑ / ↓ changent l'ordre d'affichage sur le site. "visible": true = la prestation apparaît sur le site ; "visible": false = elle est cachée (masquée) sans être supprimée. L'interrupteur « visible » de chaque carte est différent de celui du panneau « Visibilité du site » : celui-ci masque une prestation précise, l'autre masque des sections entières.

Images principales

images.hero / images.contact / images.portrait

Les trois grandes photos du site : image d'accueil, fond de la section contact, portrait de Morgane.

"images": { "hero": "images/hero-chien.jpg", "portrait": "images/portrait-morgane.jpg" }

Seul le nom du fichier est demandé dans l'admin (ex. hero-chien.jpg) — le dossier n'est pas à taper, il est ajouté automatiquement devant. Mais le fichier lui-même doit être envoyé sur OVH dans un dossier appelé images, situé juste à côté d'index.html à la racine du site.

Galerie photo

galerie (liste d'objets)

Les photos de chiens accompagnés, chacune avec son nom de fichier et son texte alternatif (accessibilité + référencement).

"galerie": [ { "src": "images/galerie/chien1.jpg", "alt": "Chien en balade en forêt" } ]

Comme pour les images principales, seul le nom du fichier (ex. chien1.jpg) est à taper dans l'admin. Mais le fichier envoyé sur OVH doit lui être placé dans galerie, un sous-dossier à l'intérieur du dossier images — pas directement dans images.

La section Galerie n'apparaît sur le site que si deux conditions sont réunies en même temps : au moins 5 photos ici, et l'interrupteur « galerie » réglé sur true (allumé) dans « 👁 Visibilité du site ».

Menu de navigation

nav (liste d'objets)

Le texte des liens du menu, dans l'ordre où ils apparaissent en haut du site.

"nav": [ { "id": "presentation", "label": "Présentation" }, { "id": "cours", "label": "Cours & tarifs" } ]

id doit correspondre exactement à l'identifiant d'une section du site (voir la structure du site ci-dessous) — seul label (le texte visible) est à modifier ici. Le lien « Galerie » s'ajoute tout seul dès 5 photos.

Couleurs du site

theme.*

9 couleurs (fond, texte, accents dorés…) qui habillent l'ensemble du site.

"theme": { "gold": "#ab8f66", "paper": "#fbf7ec" }

Le mini-aperçu du panneau s'illumine en survolant un champ, pour repérer où chaque couleur s'applique avant de valider.

Pied de page

footer.*

Le copyright et la petite phrase tout en bas du site.

"footer": { "copyright": "Momox Dogs — Morgane, éducatrice canine (BPE)" }

Référencement (SEO)

seo.*

Le titre et la description utilisés par Google et par les réseaux sociaux quand le site est partagé.

"seo": { "siteTitle": "Momox Dogs — Morgane, éducatrice canine (BPE)", "siteUrl": "https://momox-dogs.fr" }

Ces champs ne changent rien à l'apparence du site lui-même, seulement à ce qui s'affiche dans les résultats de recherche et les aperçus de partage.

Trois outils globaux ne sont pas des panneaux et ne modifient rien tant qu'on ne clique pas dessus :

  • « 👁 Aperçu du site » (en haut) : montre le rendu réel du site avec les modifications actuelles, sans rien publier.
  • « 📘 Guide complet » (en haut) : ouvre cette aide.
  • La barre du bas (↶ annuler, ↷ rétablir, charger un fichier, copier le JSON, ⬇ Télécharger content.json) : le bouton de téléchargement est la seule action qui produit le fichier à envoyer sur OVH.

🏗️ La structure du site

index.html affiche toujours les mêmes sections, dans le même ordre. Chacune est alimentée par une partie précise de content.json — c'est ce lien qui explique pourquoi modifier l'admin change le site sans jamais toucher à index.html.

  • #accueil En-tête + grand titre — alimenté par hero.*
  • #presentation « Bonjour, je suis Morgane » — alimenté par presentation.*, portrait par images.portrait, étiquettes par tags
  • #pourquoi Pourquoi suivre des cours — pourquoi.* · s'affiche seulement si visibility.pourquoi vaut true
  • #cours Grille des prestations — générée automatiquement depuis services (une carte par prestation dont visible vaut true)
  • #galerie Galerie photo — générée depuis galerie · visible seulement si 5 photos ou plus et visibility.galerie à true
  • #contact Email, téléphone, zone, réseaux sociaux, carte — contact.* · réseaux et carte masquables un par un via visibility.facebook, visibility.instagram, visibility.map (chacun à false pour cacher)
  • pied de page Copyright + phrase de fin — footer.*

Le menu de navigation en haut de page (nav) pointe vers ces sections par leur identifiant (presentation, pourquoi, cours, contact…) : c'est pourquoi seul le texte affiché (label) doit être modifié dans l'admin, jamais l'id.

Cliquer sur une carte de la section « Cours » ouvre une fiche détaillée (fenêtre modale) avec la description complète de la prestation — elle aussi générée automatiquement à partir de services, sans panneau dédié.

🗂️
Trois fichiers, trois rôlesindex.html = la structure et le design du site (fixe) · content.json = tous les textes, prix et réglages (modifié via l'admin) · admin.html = cette page d'édition, qui ne fait qu'écrire un nouveau content.json à télécharger — elle n'a pas besoin d'être « publiée » elle-même sur OVH pour que le site fonctionne.

✏️ Modifier un texte, un prix ou un cours

  1. Ouvre cette page admin.html (garde-la en favori dans ton navigateur, tu y reviendras régulièrement).
  2. Clique sur le panneau qui t'intéresse pour le déplier (ex. « Cours & tarifs », « Coordonnées de contact »…) et modifie directement les champs. Chaque changement est enregistré tout seul au fur et à mesure.
  3. Utilise le panneau « 👁 Visibilité du site » ou l'interrupteur sur chaque cours si tu veux cacher temporairement un élément sans le supprimer.
  4. Clique sur « 👁 Aperçu du site » en haut pour vérifier le rendu avant de publier quoi que ce soit.
  5. Une fois satisfaite, clique sur « ⬇ Télécharger content.json » tout en bas de la page. Le fichier part dans ton dossier Téléchargements.
⚠️
Le nom du fichier compteTon navigateur peut renommer le fichier téléchargé en content (1).json s'il en existe déjà un dans le dossier Téléchargements. Avant de l'envoyer sur OVH, vérifie qu'il s'appelle bien exactement content.json (renomme-le si besoin).
5

📷 Changer ou ajouter une photo

Une photo se gère en deux temps : préparer le fichier, puis l'envoyer sur OVH au bon endroit.

  1. Prépare le fichier sur ton ordinateur ou ton téléphone : renomme-le sans espaces ni accents ni majuscules — utilise des tirets. Ex. photo-chien-1.jpg, pas Photo Chien (1).JPG.
  2. Format .jpg ou .webp de préférence, et une taille raisonnable (idéalement sous 1-2 Mo, ~1600 px de large) pour que le site reste rapide.
  3. Dans l'admin, indique uniquement le nom du fichier dans le champ prévu (ex. dans une prestation, ou dans « Images principales ») — le dossier images/ est ajouté automatiquement, pas besoin de le taper.
  4. Envoie ensuite le fichier photo lui-même sur OVH, dans le dossier images du site (ou dans son sous-dossier galerie pour les photos de chiens) — voir l'étape 6 ci-dessous pour la manière de l'envoyer.
⚠️
Le nom doit correspondre exactementSur l'hébergement OVH, majuscules et minuscules comptent : si l'admin indique chien.jpg mais que le fichier envoyé s'appelle Chien.JPG, la photo n'apparaîtra pas sur le site.
6

🚀 Publier les changements sur OVH

🛠️
Le site est hébergé chez OVHIl faut se connecter à l'espace client OVH pour déposer les fichiers modifiés (content.json et/ou les photos). Deux façons de faire, du plus simple au plus complet :

Option A — le gestionnaire de fichiers OVH (le plus simple, dans le navigateur)

  1. Va sur https://www.ovh.com/manager/ et connecte-toi avec l'identifiant du compte OVH.
  2. Dans le menu de gauche, ouvre « Web Cloud » puis « Hébergements », et sélectionne l'hébergement du site (ex. momox-dogs.fr).
  3. Va dans l'onglet « FTP-SSH » : si un « Gestionnaire de fichiers » est proposé, ouvre-le directement depuis le navigateur — inutile d'installer quoi que ce soit.
  4. Ouvre le dossier www (c'est la racine du site, là où se trouve index.html).
  5. Pour content.json : sélectionne le fichier existant, supprime-le ou utilise « Envoyer un fichier » en choisissant le nouveau content.json téléchargé à l'étape 4 — il doit remplacer l'ancien, au même endroit.
  6. Pour une photo : ouvre le dossier images (ou images/galerie) et envoie le fichier photo de la même façon.

Option B — un logiciel FTP comme FileZilla (si le gestionnaire web n'est pas disponible)

  1. Dans le Manager OVH, onglet « FTP-SSH » de l'hébergement, récupère : le serveur FTP, l'identifiant et le mot de passe (ou crée un identifiant FTP dédié si besoin).
  2. Installe et ouvre FileZilla (gratuit), renseigne ces trois informations dans « Connexion rapide » et connecte-toi.
  3. À droite (le serveur OVH), va dans le dossier www.
  4. À gauche (ton ordinateur), retrouve le fichier content.json téléchargé (ou la photo).
  5. Glisse-dépose le fichier de gauche vers www à droite, et confirme le remplacement (« Overwrite ») quand FileZilla le demande.
💾
Avant d'écraser un fichierTélécharge une copie de l'ancien content.json depuis OVH sur ton ordinateur avant de le remplacer (renomme-la par exemple content-avant-15-08.json). Si quelque chose ne va pas, tu pourras toujours revenir en arrière.
7

🔍 Vérifier que la mise à jour est bien en ligne

  1. Ouvre le site dans le navigateur (l'adresse habituelle) et vérifie que le changement apparaît.
  2. Si tu ne vois pas encore le changement, force le rafraîchissement de la page : Ctrl + F5 sur ordinateur (ou Cmd + Maj + R sur Mac) — le navigateur garde parfois une ancienne version en mémoire.
  3. Jette aussi un œil sur téléphone, en navigation privée si besoin, pour être sûre que tout le monde voit la nouvelle version.

🩹 Problèmes potentiels & comment les corriger

Affichage général du site

Le site n'affiche plus rien / semble cassé après une mise à jour

Cause probable : le content.json envoyé sur OVH est incomplet, corrompu, ou n'est pas celui généré par l'admin (ex. modifié à la main).

Solution : renvoie sur OVH la copie de sauvegarde de l'ancien content.json (voir l'astuce de l'étape 6) pour revenir à une version qui fonctionnait, puis recommence la modification depuis l'admin.

Une section a disparu du site alors que je n'y ai pas touché

Cause probable : son interrupteur dans « 👁 Visibilité du site » a été désactivé par erreur, ou — pour la Galerie — le nombre de photos est repassé sous 5.

Solution : ouvre le panneau « Visibilité du site » et réactive l'interrupteur concerné ; pour la Galerie, vérifie aussi le nombre de photos dans son panneau.

Images

Une photo n'apparaît pas sur le site

Cause probable : le nom tapé dans l'admin ne correspond pas exactement (majuscules/minuscules comprises) au nom du fichier envoyé sur OVH, ou le fichier n'est pas dans le bon dossier.

Solution : renomme le fichier ou corrige le champ pour qu'ils soient identiques au caractère près, et vérifie qu'il est bien dans images/ (ou images/galerie/ pour la galerie).

L'aperçu dans l'admin montre une image cassée

Cause probable : le fichier indiqué n'existe pas encore à cet emplacement — normal si la photo n'a pas encore été envoyée sur OVH.

Solution : aucune action dans l'admin ; l'image s'affichera dès que le fichier sera déposé au bon endroit sur OVH (voir l'étape 6).

Le formulaire d'admin lui-même

content.json refuse de se charger dans l'admin

Cause probable : le fichier a été modifié à la main (hors admin) et contient une faute de syntaxe, ou ce n'est pas le bon fichier.

Solution : un message d'erreur explique le problème rencontré ; charge plutôt une sauvegarde précédente qui fonctionnait, via le bouton de chargement de fichier.

Un champ reste bordé de rouge

Cause probable : il est obligatoire et vide, ou mal formaté (ex. une adresse e-mail sans « @ », un lien sans https://).

Solution : corrige le champ signalé avant de télécharger — le bouton de téléchargement reste utilisable, mais mieux vaut tout corriger d'abord.

Mes modifications d'hier ont disparu

Cause probable : l'admin garde un brouillon automatique dans le navigateur utilisé — si un autre navigateur, un autre ordinateur, ou la navigation privée a été utilisé entre-temps, ce brouillon n'est pas partagé.

Solution : travaille toujours depuis le même navigateur pour un brouillon en cours, et télécharge content.json dès qu'une série de modifications est terminée — c'est ce fichier, une fois publié sur OVH, qui devient la seule vraie source commune à tout le monde.

Publication sur OVH

J'ai bien envoyé le fichier mais rien ne change sur le site

Cause probable : le fichier téléchargé s'appelait content (1).json (renommage automatique du navigateur) et n'a donc pas remplacé l'original sur OVH, ou le navigateur affiche une version en mémoire (cache).

Solution : vérifie sur OVH que le fichier s'appelle exactement content.json, puis force le rafraîchissement de la page (Ctrl+F5, voir l'étape 7).

Un lien du menu de navigation ne mène nulle part

Cause probable : le champ id d'une entrée du menu a été modifié — il doit toujours correspondre à l'identifiant d'une section réelle du site (voir « La structure du site »).

Solution : dans le panneau « Menu de navigation », ne modifie que le texte affiché ; si l'ordre ou le contenu semble incohérent, recharge la dernière sauvegarde connue de content.json.

💡
Le réflexe qui évite la plupart des problèmesAvant tout envoi sur OVH : utilise « 👁 Aperçu du site » pour voir le rendu réel, et garde toujours une copie de sauvegarde de l'ancien content.json avant de le remplacer.
